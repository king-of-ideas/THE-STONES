# ZYPC 2026 新生赛 Writeup

**参赛者：** 张宇翔（GBKer）  
**最终得分：** 1372  
**排名：** 20  
**解出题数：** 19  

## 一、 写在前面（个人背景与赛后反思）

本次比赛是我第一次正式参加 CTF 竞赛。我目前的语言基础是 C 语言（学到结构体与指针），以及初步的 Python 基础。Web 方向的基础较为薄弱，密码学知识也主要依赖于 BugKu 的入门练习。

在比赛过程中，我采取了“具体问题具体分析”的策略：以 Python 脚本和 WSL 环境为工具，以 C 语言的逻辑推演为底层思路，同时借助 AI 进行辅助生成基础脚本代码，但在执行和排错时尽量去理解其底层逻辑。

虽然因为 Web 和无网环境经验不足，留下了些许遗憾，但本次比赛让我切实感受到了解构系统和底层推演的乐趣。

## 二、 密码学（Crypto）篇：逻辑与数学的博弈

### 1. Vigenère
- **思路**：题目给定了十六进制形式的密钥 `\x7a\x79\x70\x63\x7a\x79`，将其转换后得到 `zypczy`。根据题目提示的“手算”要求，我在草稿纸上手动推演了字母偏移。利用标准维吉尼亚解密公式 `明文 = (密文 - 密钥) mod 26`，逐字还原出明文 `zypc{1_see_vigenere}`。
- **反思**：基础密码学需要耐心，工具生成虽然快，但手推能帮我直观理解加密过程。

### 2. ez_xor（已知明文攻击）
- **思路**：题目给出了 `challenge.py` 和一段密文。由于 flag 格式固定为 `zypc{`，我利用已知明文攻击，将密文前 5 个字节与 `zypc{` 进行异或，推算出密钥为 `0x5a`。随后编写 Python 脚本，对全部密文进行异或解密，得到 `zypc{D0_You_know_AEs}`。
- **工具辅助**：AI 帮我理清了 `bytes.fromhex()` 和异或运算的 Python 语法，脚本逻辑由我编写并在 WSL 中运行验证。

### 3. RC4（密钥重用漏洞）
- **思路**：分析源码发现 `WELCOME_MSG` 和 `FLAG` 使用了相同的密钥 `KEY`。对于流密码，密钥重用会导致相同的密钥流。
- **推演**：利用公式 `明文2 = 密文2 XOR 密钥流 = 密文2 XOR 密文1 XOR 明文1`。用 Python 编写利用脚本，成功解密出 flag。

### 4. X-box（已知明文攻击与爆破）
- **思路**：源码使用 `random.seed(num)` 生成 S 盒。虽然种子未知，但 S 盒的置换特性意味着相同的索引会映射到相同的值。
- **攻击**：我利用已知明文 `zypc{` 的 ASCII 码，在脚本中匹配密文前 5 个数字。经过 Python 脚本爆破，发现种子极小（仅为 `10`），随后反推 S 盒成功解密全部明文。

## 三、 图形与编码（Misc）篇：打破思维定势

### 1. 黄道十二宫
- **思路**：题目提示了“下一个字符为当前位置向下移动一行，向右移动两列，越界则循环”。我根据这个矩阵步进逻辑，用 AI 编写了 Python 脚本进行网格读取，解出了 `zypc{zodiac_killer_one_day_it_will_be_deciphered!}`。

### 2. 佛曰
- **思路**：识别出是古典密码“与佛论禅”。使用在线工具解密时，发现提示需要箴言。
- **推演**：仔细观察题目故事，发现核心句是“每一天”。将“每一天”作为密钥填入工具，成功解密。

### 3. 巴别塔圣歌（语义与视觉破局）
- **思路**：这是我最喜欢的一道题。题目给出几张带有自定义符号的图片。
- **陷阱与破局**：初期我顺着题目背景“W型”推导，以为是 Mountain 的猪圈密码变体。但随后发现密文符号数量刚好是 14 个，结合图 2 的“眼睛”（EYES），我跳出了纯符号替换的定势，结合语义“I see you mean(懂你意思)”，得出 flag。
- **结果**：确认明文为 `zypc{i-see-you-mean}`，成功解出。

## 四、 Web与图片隐写篇：踩坑与排错

### 1. 流光焰火（Git 泄露排查链）
- **发现**：根据提示“运营人员的交接痕迹”，对靶机进行目录扫描，发现 `.git/config` 返回 200。
- **受阻**：尝试 `wget -r` 下载整个 `.git` 目录时，被服务器返回 403 Forbidden 拦截。
- **绕过与深入**：改用 `curl` 逐文件请求。成功获取 `logs/HEAD` 日志，发现历史提交记录。
- **底层突破**：手动编写 Python 脚本，通过 `zlib` 库解压 Git 的 commit 和 tree 对象，成功还原了源码目录结构，定位到了 `notes` 目录。可惜后续访问目录再次遭遇 403 拦截，未能拿到最终 flag。
- **经验**：这证明了 Web 安全不仅要会用现成工具，更要懂协议底层的对象结构。这比单纯拿到一个 flag 更有价值。

### 2. 风景秀丽的小岛（图片隐写）
- **尝试**：下载附件后，我在 WSL 中使用 `exiftool` 检查元数据，使用 `strings` 和 `binwalk` 尝试寻找隐藏文件，均未发现异常。
- **高度隐写尝试**：针对提示“横看成岭侧成峰”，我编写了 Python 脚本修改 JPEG 文件头中的 SOF0 高度字段，试图将高度扩展到 2048。但打开图像后，底部仅有灰色空白，推断可能是 LSB 隐写或需其他特定工具。
- **状态**：未解出，留待赛后继续学习。

### 3. 其他 Web 题（反序列化、SSRF）
- 在 `showflag` 题中，理解了 PHP 反序列化的基本构造，但在传参时发现参数名带点号（`data_ZYPC.CTF`）会被 PHP 转换为下划线，导致参数获取失效。
- 在 `我...回来了？` 中，通过 F12 观察到前端 SPA 架构，推测可能存在 SSRF，但由于时间关系未能进一步探明内网请求接口。

## 五、 总结

本次比赛，我深刻体会到了“生存是最好的老师”。面对各类题目，我经历了无数次报错、环境配置冲突（如 WSL `pip` 环境的 `externally-managed-environment` 报错）、浏览器控制台防粘贴拦截（中文“允许粘贴”）。

**我的优势在于：** 遇到环境阻力时，我能灵活切换工具。例如从浏览器转战 `curl`，从直接运行 Python 代码转战创建本地 `.py` 文件，从在线工具转战本地脚本。
**我的不足在于：** Web 框架底层知识和无网实战经验还比较欠缺。

未来在智邮普创的学习中，我会继续发挥 C 语言底层的逻辑优势，补齐 Web 安全与二进制安全的短板，不依赖现成脚本，努力做到“掌握系统、自由构建”。
